# HR Daily

Система персональной ежедневной HR-отчётности РП.

## Роли

- **Сотрудник** видит только главную страницу и собственный отчёт. В таблице отображаются все РП, но редактировать можно только назначенные; текущий день редактируется, остальные даты доступны только для просмотра.
- **Администратор** видит сводные суммы всех сотрудников, фильтрует отчёт по сотруднику и управляет сотрудниками, РП и ориентиром плана.
- **Суперадминистратор** обладает полным административным доступом, не связан со справочником сотрудников, не показывается в списке и не может быть удалён.

Суперадминистратор создаётся автоматически из обязательных переменных `SUPERADMIN_LOGIN` и `SUPERADMIN_PASSWORD`.

## Возможности

- отдельный персональный отчёт каждого сотрудника на каждую дату;
- агрегированная таблица администратора и фильтр по сотруднику;
- редактирование сотрудником только текущей даты;
- временное открытие администратором доступа к прошедшим датам на 24 часа с возможностью досрочного закрытия;
- управление логинами, паролями и ролями;
- получение списка РП напрямую из Debtster API при открытии отчёта за текущий день начиная с 28.08.2026;
- отображение в отчёте за любую выбранную дату штатных позиций, активных сотрудников, вакансий, стажёров, подбора и планируемого резерва из Debtster API; данные доступны только для чтения, а первое полученное за день количество стажёров сохраняется для отображения последующих изменений по каждому РП и в итоговой строке;
- автоматическое обновление отчёта по вакансиям Debtster каждые пять минут, пока вкладка с РП-отчётом активна;
- отдельные планы по приглашённым и принятым кандидатам для каждого сотрудника, независимо для РП и ГО;
- изменение обоих планов сотрудника прямо из отчёта только на выбранный рабочий день;
- Excel-подобная таблица с живыми итогами и процентами исполнения планов по приглашённым и принятым кандидатам;
- отдельная административная выгрузка XLSX за период с выбором РП, ГО или обоих отчётов: сначала общая таблица, затем отдельные таблицы каждого сотрудника; для РП открытые вакансии, стажёры и количество планируемого резерва за любой период берутся из снимка Debtster на конечную дату периода без выгрузки ФИО планируемых к увольнению;
- отдельные листы XLSX с принятыми сотрудниками (включая должность), списками ФИО по кадровым показателям и ответственными владельцами отчётов;
- ориентир плана по умолчанию `16`, который не ограничивает ввод и не блокирует сохранение;
- PostgreSQL, Docker Compose, REST API и HttpOnly-сессии.

Импорт, история и журнал действий временно исключены из интерфейса.

## Запуск

```bash
cp .env.example .env
docker compose build
docker compose run --rm backend /app/hr-server migrate
docker compose up -d
```

Откройте <http://localhost:6770> и войдите под суперадминистратором из `.env`. Сразу после первого входа смените тестовые значения паролей для production-окружения.

Все переменные обязательны: Docker Compose использует `${VAR:?message}` без значений по умолчанию.

| Переменная | Назначение |
|---|---|
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | PostgreSQL |
| `DATABASE_URL` | Строка подключения с host `postgres` |
| `DEBTSTER_API` | Базовый URL Debtster API без пути `/api/v1/...` |
| `HTTP_ADDR` | Внутренний адрес Go-сервера |
| `STATIC_DIR` | Каталог frontend |
| `APP_SECRET` | Секрет подписи сессий |
| `SUPERADMIN_LOGIN` | Логин системного суперадминистратора |
| `SUPERADMIN_PASSWORD` | Начальный пароль суперадминистратора |
| `APP_PORT` | Входной порт, в примере `6770` |
| `DOCKER_NETWORK` | Обязательное имя существующей внешней Docker-сети |

## Проверки

```bash
go test ./...
cd web && npm install && npm run build
```

Миграции никогда не запускаются сервером автоматически. Перед первым запуском и после
добавления новых SQL-файлов их нужно применить отдельной командой:

```bash
docker compose run --rm backend /app/hr-server migrate
```

Перед миграцией и запуском можно отдельно проверить доступность Debtster API. Команда
ничего не записывает в базу данных и проверяет как список РП, так и отчёт по вакансиям
за текущую дату:

```bash
docker compose run --no-deps --rm backend /app/hr-server check-debtster
```

Выполненные версии и их контрольные суммы хранятся в таблице `schema_migrations`; SQL-файлы
встроены в Go-бинарник. Имя существующей внешней Docker-сети задаётся обязательной
переменной `DOCKER_NETWORK`. Если сети ещё нет, создайте её командой
`docker network create <имя_сети>`.
